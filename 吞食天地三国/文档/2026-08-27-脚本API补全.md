# 网页复刻引擎脚本 API 覆盖补全（G3-R1，2026-08-27）

> 范围：`吞食天地三国/网页复刻/吞食天地Ⅱ同人复刻-网页版/`。数据（566 地图 + 公共事件）脚本引用的 `$game*` API 与引擎实现的覆盖审计与补全；修复多行脚本执行与客栈链路。

## 一、审计发现（数据 → 引擎交叉核对）

对全部数据 JSON 中脚本（355/655/111-条件/122-脚本操作数）调用的 `$game*` 方法做全量普查，与引擎交叉核对后确认以下**静默失效**缺口（脚本抛错被 try/catch 吞掉，功能实际不工作）：

| 数据引用 | 次数 | 引擎状态 | 影响 |
|---|---|---|---|
| `$gameParty.gold()` | 48 | ❌ getter（方法调用抛 TypeError） | 全 data 中「金>=x」类脚本条件恒为 false |
| `$gameActors.actor(id)` | 339 | ❌ 全局缺失 | 所有 map 事件脚本角色操作失效 |
| `$gameParty.innPrice(n)` | 48 | ❌ 缺失 | 客栈脚本定价恒 0 |
| `$gameParty.changeLevel(n)` | 18 | ❌ 缺失 | 剧情升/降级失效 |
| `$gameParty.addSurrenderedEnemy/hasSurrenderedEnemy` | 24/6 | ❌ 缺失 | 收服敌将(颜良/文丑)链路失效 |
| `$gameParty.changeEquipChengHao/hideChengHao` | 6/6 | ❌ 缺失 | 称号穿戴失效 |
| `$gameParty.gainWinPoint` / `inBattle` / `menuActor` | 2/1/1 | ❌ 缺失 | 胜点/上下文访问失效 |
| `$gameParty.changePvpLevel/addPvpCount` | 1/1 | ❌ 缺失 | PVP 计数失效 |
| **多行脚本**（355 + 655 续行） | 多处 | ❌ **逐行执行** | `forEach(actor=>{` 等块首行语法错误被吞 → CE5 客栈治愈等全部失效 |
| `actor.addOwnTalent` / `actor.changeLevel(lv,show)` | 1/1 | ❌ 缺失 | 天赋授予/剧情等级失效 |

另确认两处上下文缺口：`valueOperand` 脚本操作数（122/125-128 的脚本值）无 `with(T)` 上下文；`$gameVariables.value` 等本身正常。

## 二、修复内容（文件归属：data.js / interp.js / battle.js / menus.js / windows.js）

1. **`Game_Party.gold()` 改为方法**（数据脚本全部以 `gold()` 调用），引擎内部 6 处读取同步改 `gold()`（interp.js×3 / menus.js 商店 / windows.js 消息与金钱窗×2）；存档序列化本就使用 `_gold`，不受影响。
2. **`Game_Party.innPrice(rate)`**：客栈定价。公式为**推定值** `rate×4`（基础 4 金/档），与部分客栈硬编码 var6=4 一致，待原版实机比对校准。
3. **`T.$gameActors` 全局 + installGlobals 注册**：`{actor(id){return T.getActor(id)}}`，恢复 339 处角色脚本。
4. **`Game_Actor.changeLevel(lv, show)`**（绝对等级设定，支持剧情升级/二周目重置脚本）与 **`addOwnTalent(id)`**（天赋持有存储，天赋系统主体留待后续）。
5. **`Game_Party.changeLevel(lv)`**：全队同步到绝对目标等级（配合 Tstd_LvUp 音效的剧情里程碑）。
6. **`Game_Party` 其余缺口最小实现**：`addSurrenderedEnemy/hasSurrenderedEnemy`（收服列表）、`gainWinPoint`、`changePvpLevel/addPvpCount`、`inBattle()`、`menuActor()`、`changeEquipChengHao/hideChengHao`（称号存储）。
7. **多行脚本累积执行**（三处同语义修复）：地图解释器 interp.js、菜单道具迷你执行器 data.js `runMapCommonEvent`、战斗公共事件执行器 battle.js `runBattleCommonEvent` —— 355 收集其后连续 655 续行拼成完整脚本一次执行；游离 655 忽略。
8. **`valueOperand` 脚本操作数补 `with(T)` 上下文**（interp.js）。

缓存版本号 `?v=20260827` → `?v=20260827-r4`（与并行会话共用 index.html，版本号统一在 r4）。

## 三、实测证据（headless Chrome + CDP，全程零异常零 console 错误）

### 客栈端到端（`测试/tools/cases/inn-core.pre/end.json`，map154 住宿）
- `?autostart&autointro=18&goto=154,18,11` → 自动走到宿店老板面前由 autointro 确认：111 条件 `$gameParty.gold() >= $gameVariables.value(6)` 为真（修复后）→ 125 扣款 **恰 4 金** → CE5 多行脚本（355+655 累积）治愈 **刘备 5/216 → 216/216、谋 3/20 → 20/20**；var6=4；
- 对照组（未修复前）：金币 0 时条件为假 → 正确显示「对不起，您的金不够！」（验证条件分支本身无误）；
- **allOk=true**（cond/paid4/healed/var6 全过）。

### API 电池（同用例内）
- `innPrice(1/2/5)=[4,8,20]`；`$gameActors.actor(1).name` 可读；`addOwnTalent(102)`→`_ownTalents=[102]`；
- `changeLevel(3)` → 全队 `[3,3,3,3]`；`addSurrenderedEnemy(114)/hasSurrenderedEnemy(114)=true`；

- `actor(1).changeLevel(1,false)=1`（二周目重置脚本路径）。

### 阵型回归（敌方/阵营隔离/倍率，`formation.pre/end.json` 重跑）
- 全部 **allOk=true**：敌方鹤翼阵 atk/def ×1.25 精确、我方背水阵乘算 [30,10,200,152,185]、阵营隔离、`%2` 消息——确认 `gold()`/data.js 改动未破坏战斗与阵型链路。
