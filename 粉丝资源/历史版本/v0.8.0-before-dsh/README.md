# 粉丝资源

创意空间的独立子项目，集中管理视频里提到的网址、模板、口令与下载资料。当前保留 `01`～`06` 六条资源；本次发布版本为 `content/fan-resources/v0.8.0`（上一正式版本为 v0.7.1），2026-10-26～27 的审查增强记录见 `project.md` 与 `更新记录.md`，发布状态以创意空间的线上验收为准。

## 目录与职责

| 文件/目录 | 职责 |
| --- | --- |
| `resources.json` | 唯一资源目录：编号、标识、日期、标题、简介、详情页地址 |
| `index.html` | 粉丝资源列表布局、搜索入口和加载状态 |
| `scripts/catalog.js` | 浏览器与 Node 共用的数据校验、固定编号排序、搜索规则 |
| `scripts/resources.js` | 加载/超时/失败重试、列表渲染、搜索与结果数 |
| `scripts/copy.js` | 六个详情页的复制、失败提示、键盘焦点和读屏反馈 |
| `styles/common.css` | 触屏按钮、焦点样式、手机导航和公共交互样式 |
| `资源/<资料名>/index.html` | 独立资料页，长资料与复制内容在此维护 |
| `测试/` | 零依赖回归与可选浏览器回归 |
| `历史版本/` | 版本及审查前源码快照，禁止当成当前代码修改 |
| `project.md`、`更新记录.md` | 交付决策、QA、源码 SHA-256 与阶段记录 |

创意空间首页读取本项目的 `resources.json` 做展示；修改首页展示逻辑须回到创意空间任务。Mac 软件资源库已于 2026-09-10 迁为平级项目；本项目的 `资源/Mac软件资源库/` 仅保留旧 URL 兼容跳转，不保存软件数据、不占编号。

## 使用与维护

- 列表支持固定编号（`6` / `06` / `０６`）、标题及简介关键词搜索；多个关键词以空格分隔，不区分英文大小写。筛选结果数与目录总数分开显示。
- 加载超时为 10 秒，覆盖请求与正文读取。网络错误、错误 JSON 和不合约定的数据会显示失败与重试入口；空目录显示独立空状态。
- 新资源加入 `resources.json`：`number` 为 `01`～`99` 两位编号，`id` 为小写英文/数字/连字符标识，`date` 为真实的 `YYYY-MM-DD` 日期，`title` 与 `summary` 必填。
- `detailUrl` 必须为 `./资源/<资料名>/`，编号、id 和地址不得重复；禁止绝对地址、查询、锚点、转义路径和父目录跳转。详情页仍需在本项目内存在。
- 普通复制按钮放在 `.template-block` 内，复制内容用 `.template-text`；跨块复制用 `data-copy-target` 指向唯一元素 ID。不要查询整页第一个 `.template-text`，前面的文件名/说明也可能使用该样式。
- 六个资料页都加载 `../../scripts/copy.js` 和 `../../styles/common.css`。复制失败提示保留，允许重试和手动选取；保留页面正文，使禁用脚本时仍可阅读资料。
- 修改前在 `历史版本/` 保存将被替换的源码；修改后运行回归，更新本项目记录和创意空间本地总记录。根目录总记录不上传。

## 本地预览与测试

线上页面无框架、无第三方运行时依赖。基础回归用 Node.js 18+；本轮使用 Node.js 24.20.0。预览可使用 Python 3：

```sh
# 在粉丝资源目录运行，父目录作为网站根目录，以保留返回首页与旧入口跳转。
python3 -m http.server 8000 --bind 127.0.0.1 --directory ..
```

打开 <http://127.0.0.1:8000/粉丝资源/>。不要直接双击列表页：浏览器通常会禁止 `file://` 页面读取 JSON，页面会提示通过网站或预览服务打开。

基础回归（无需 npm 安装）：

```sh
node 测试/resources_test.js
node 测试/catalog_validation_test.js
node 测试/clipboard_test.js
node 测试/legacy_routes_test.js
node 测试/package_test.js
```

真实浏览器回归需要本机 Google Chrome 与 Playwright；测试使用独立浏览器上下文、本地服务及受控剪贴板，不连接用户浏览器登录态。安装依赖与截图只放忽略目录：

```sh
npm install --prefix 测试/.artifacts/browser --no-save playwright@1.62.1
node --test 测试/browser_test.cjs
```

已有 Playwright 时可用 `PLAYWRIGHT_MODULE_PATH` 指向其模块目录；用 `BROWSER_CHANNEL` 切换已安装的兼容浏览器。本轮测试 21 项，包含 6 个详情页 × 5 种剪贴板环境，以及 7 个页面 × 5 种宽度（320/375/768/820/1280）。截图和运行日志保存在 `测试/.artifacts/`，不提交、不发布。

仓库统一门禁：在创意空间根目录运行 `node scripts/check-all.cjs`。该入口自动发现本项目的 `*_test.js`（含隔离发布包测试），浏览器回归需按上面的命令单独运行。全仓门禁失败时按所属项目处理，不能将本项目通过等同于整个站点可发布。

## 发布与恢复

1. 保留 `resources.json`、入口、资料页、`scripts/` 和 `styles/` 的完整相对目录；新增外部脚本和 CSS 都必须随页面部署；共享 `scripts/build-site.cjs` 已纳入本项目 `styles/`，`package_test.js` 会在隔离目录实际构建并核验所有页面依赖。
2. 运行基础回归、浏览器回归及统一门禁，补齐项目记录和源码校验。
3. 由创意空间统一提交、按 `content/fan-resources/vX.Y.Z` 打标签并推送 `main`；标签本身不触发部署。
4. 等待 Pages 完成，跟随真实入口检查脚本、数据、详情页和复制功能，验收后才算发布完成。

重装后先读 `AGENTS.md` 与本文件，再读 `project.md` 最新记录；Node 基础测试和 Python 预览即可恢复日常维护。浏览器依赖按需重装，不依赖某个临时缓存路径。历史索引见 `更新记录.md`、`历史版本/README.md`；2026-10-27 审查前的完整工作区快照在 `历史版本/2026-10-27-review-before/manifest.json`，包含前一天未发布的复制修复，以及本轮共享打包配置的修改前快照。

## 已知边界与后续方向

- 外部网盘/官网链接的实际文件、权限和有效期由第三方控制；源码测试只能确认按钮、链接与展示一致，不能用 HTTP 200 替代文件可下载的验证。发布前按现有资源核验流程复查。
- 当前数据量适合轻量编号/关键词搜索；数量增长后可按用户需要加入分类字段与筛选，不必先引入数据库或前端框架。
- 复制环境可能禁用所有自动复制接口，手动选取文字是保留的正常回退途径。
