## 规则与跨项目关系（Standards）

- 首页继续只读取目录和粉丝资源，数据所有权不变；Mac 保持独立平级项目，旧目录仅为兼容跳转，不占资源编号。
- 版本生成器只取当前提交可达的语义标签，临时 Git 仓库验证未合并分支、annotated 标签、旧提交和工作目录；生成目录与版本测试不再因 Mac 状态或未来版本号漂移失败。
- 发布验收原本在根页面、三国实际引擎或 Mac 数据 404 时仍可能成功；现在跟随跳转，检查实际脚本/数据，拒绝空目录，HTTP 200 旧提交也重试，所有请求有超时。
- 新增根 `scripts/check-all.cjs` 门禁。工作流固定 Node 24 / Python 3.12 + Pillow，只允许 `main` 自动或手动部署，分支并发组隔离。
- 新增 `.site/` 发布打包，仅包含运行文件并维持现有网址。原 HEAD 跟踪文件总量约 **202.6 MiB**，新运行包约 **45.7 MiB**（约少77%，未压缩口径；不是传输时间测量）。旧版本、测试、开发资料、原生实验代码不再打包。
- 发布包测试逐层核对文件大小写，避免 macOS 本地能读但 GitHub Pages 404。当前包 **1742 文件**，静态引用完整、**21 段 JavaScript** 语法通过。
- 同步项目关系、恢复指南和文件夹说明中的过时版本、资源数量、三国测试对象及 HTTP 运行方式。

最高影响的联动问题是发布检查可能误报成功；已用故障 HTTP 服务验证新的失败路径。CI 配置与脚本在本地验证，本轮没有触发 Linux GitHub Actions 新部署。
