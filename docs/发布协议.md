# 创意空间 · 统一发布协议

本协议适用于创意空间的全部子项目：创意空间首页、坦克大战、吞食天地三国、超级玛丽、墨水屏小站、Mac 软件资源库、粉丝资源。Mac 软件资源库自 2026-09-10 起为根目录平级项目，不属于粉丝资源。

## 原则

- 子项目负责开发、测试、项目记录和版本标签。
- 创意空间负责审核跨项目影响、首页目录联动和统一发布。
- GitHub Pages 只由 `main` 分支部署；版本标签只记录发布版本，不触发 Pages 工作流。
- “已推送”不等于“已部署”。只有 Actions 成功且线上验收通过，才能对外报告“已部署”。

## 子项目完成后

1. 只修改自己的项目文件夹。
2. 运行本项目自己的测试。
3. 更新本项目的 `project.md` 与 `更新记录.md`。
4. 提交到创意空间仓库；如果是稳定版本，创建对应 namespace 标签：
   - 游戏：`game/<id>/vX.Y.Z`
   - 首页：`site/home/vX.Y.Z`
   - 资源库：`resource/<resource-id>/vX.Y.Z`（Mac 软件资源库为 `resource/mac-software-library/vX.Y.Z`）
   - 粉丝资源：`content/fan-resources/vX.Y.Z`
5. 通知创意空间任务，内容包含：提交号、标签、测试结果、是否需要首页改动。

子项目对话不得直接宣称 Pages 已部署，除非已经看到成功的 Actions 运行和线上验收结果。

## 创意空间发布

在创意空间总协调任务中执行：

```bash
cd "/Users/sun/Desktop/AI/创意空间"
git status --short --branch
git log --oneline -5
node 创意空间首页/scripts/generate-game-catalog.cjs
node scripts/check-all.cjs
```

确认没有不属于本次发布的改动后，再按以下顺序发布稳定版本：

```bash
git tag <namespace>/vX.Y.Z
git push origin <namespace>/vX.Y.Z
git push origin main
```

Pages 工作流会在 `main` 推送时：

1. 拉取完整 Git 历史和标签。
2. 从当前提交可达的标签生成 `game-catalog.json`，使用 Node 24 / Python 3.12 + Pillow 运行全项目测试。
3. 写入当前部署提交的 `deployment-meta.json`。
4. 用 `scripts/build-site.cjs` 生成 `.site/`，验证发布文件、引用路径及大小写；仅上传运行文件，排除历史版本、测试、开发文档和原生实验代码。
5. 发布 GitHub Pages；手动运行同样只允许 `main`，不同分支的手动运行不会取消主分支部署。
6. 验收根跳转、七个板块、三国实际引擎页面/脚本/核心数据、创意目录、Mac 软件 JSON、粉丝资源数据及全部详情页脚本。

任何一步失败都不能报告发布完成。先查看 Actions 失败步骤，再决定重跑或修复。

## 线上验收

本地手动验收可以运行：

```bash
node 创意空间首页/测试/published_site_test.mjs \
  "https://sunsharebay-lgtm.github.io/TK/" \
  "<预期部署提交号>"
```

这个检查会跟随站内 HTML 跳转、验证实际脚本及数据，拒绝空目录，并在 CDN 返回 HTTP 200 旧部署标记时按配置重试提交匹配。网络请求有超时；外部分享文件的实际内容不在此 HTTP 验收范围。

新增运行文件时同步维护 `scripts/build-site.cjs` 的发布清单。预览发布包：先运行生成目录、写入标记和打包脚本，再用 `node scripts/serve-site.cjs .site 8123` 提供本地服务，运行验收脚本并使用预期提交 `local`。

## 失败处理

- `main` 有新提交但线上旧：先查 Actions 是否成功，再查 Pages 环境和部署记录。
- 标签触发环境保护错误：说明旧工作流仍在使用，确认 `pages.yml` 只监听 `main`。
- 同一提交出现多个部署运行：检查是否恢复了标签触发或并发配置。
- Actions 成功但线上验收失败：按提交标记和 HTTP 状态定位缓存、路径或部署源问题，不能只等待。
